# AUDIT 2026-07-19 — 블로그 색인 실패 진단과 구조 수정

서치콘솔/네이버 서치어드바이저에서 blog가 색인되지 않는 원인을 라이브 실측으로 진단했다.
결론: **기술 SEO는 문제가 아니다**(글 페이지 200 + 본문 SSR + canonical + `index,follow` +
JSON-LD 4종 + google/naver site-verification 확인). 원인은 신뢰/품질 신호 4가지다.

## 원인 4가지

1. **sitemap이 죽은 URL 목록**: 발행은 Windows PC에서 연속 자동인데 sitemap/RSS는
   `npm run build:spa` + firebase deploy 때만 갱신되는 정적 빌드 산출물. 15일째 미배포.
2. **URL 처분 문화**: 발행→대량 archive→404 반복. 크롤러가 "일회용 URL 사이트"로 학습.
3. **확장 AI 콘텐츠 패턴**: 일 13~26건 + 템플릿 변형 제목 + 자기참조 출처(자사 페이지 2곳)
   + 심야 버스트 = Google 2024-03 scaled content abuse 정책이 정확히 겨냥하는 프로필.
   기술 SEO가 완벽해도 사이트 단위 색인 억제가 걸린다.
4. **네이버 구조 한계**: 네이버 통합검색은 외부 도메인 웹문서를 거의 노출하지 않는다
   (C-Rank는 네이버 블로그 생태계 중심). selfhosted 글의 네이버 색인은 목표에서 제외하고,
   네이버 노출은 기획 14(naver_manual 수기 발행)로 간다.

## 근거(grounding) 병목의 뿌리 — 같은 문제의 다른 얼굴

- 2026-06-15 Tavily 제거 후 근거팩 원천은 자사 마케팅 페이지 2곳뿐(숫자 거의 없음).
- 2026-07-09 depth pivot이 "글마다 고유 비교표·체크리스트(=구체 수치)"를 요구 →
  근거에 없는 수치를 모델이 지어냄 → `local_unsupported_claims` 0.5 하드캡 →
  grounding 0.50~0.83 탈락 다발. **숫자 없는 근거 위에 숫자 콘텐츠를 지으라는 모순.**
- 네이버 검색 API 폴백은 코드에 있었으나 blog.json 스니펫만 반환 + fetch가 빈 문자열이라
  MIN_SOURCE_TEXT_LEN(300자) 필터에서 전멸 — 키를 넣어도 근거가 안 모이는 상태였다.

## 운영 반영 절차 (사람 작업 필요)

1. **배포**: `npm ci && npm run build:spa` 후 `firebase deploy --only hosting,functions`
   (functions/ 안에서 `npm ci` 선행). 배포 후 확인:
   - `curl https://beoksolution.com/sitemap.xml` — lastmod가 오늘, 최근 발행 글 포함
   - archived 글 URL 하나 → HTTP 410
2. **서치콘솔/서치어드바이저**: sitemap.xml 재제출(URL 동일하므로 "다시 크롤링" 요청).
3. **Windows 발행 PC**: git pull 후 다음 발행 주기부터 흐름 간격/윈도우 가드 자동 적용.
4. **네이버 검색 API 키**(무료, developers.naver.com): 발행 PC `.env`에
   `NAVER_CLIENT_ID`/`NAVER_CLIENT_SECRET` 설정 → 독립 근거 폴백 즉시 활성.
   안정 확인 후 `REQUIRE_EXTERNAL_EVIDENCE=true` 승격 검토.
5. **삭제 정책**: 대량 archive→404 관행 중단. 저품질 글은 삭제 대신 리라이트(URL 유지),
   불가피한 삭제만 410으로 정리.

## 남은 항목 (미적용, 다음 결정 필요)

- depth 프롬프트의 비교표·체크리스트를 "수치 표"가 아니라 "항목·기준 표"로 유도해
  근거-깊이 모순을 프롬프트 쪽에서도 완화(현재는 사후 제거+하드캡만 존재).
- `generate.py`의 `_remove_unsupported_specific_claims`가 문자열 replace 기반이라
  공백/절단 불일치로 새는 케이스 — factcheck와 동일한 문장 분할 기반으로 재작성.

## 같은 날 후속 적용 (2차 커밋)

- /blog/ SSR 페이지네이션 적용·배포 완료(페이지당 24건, 순수 a href, 페이지별
  canonical). 전체 발행 글이 링크로 발견 가능해짐 — 라이브 검증: 1페이지 24링크
  + 2~12페이지 내비, ?page=5 canonical 정상.
- IndexNow 일괄 ping 273 URL 성공(HTTP 200 — 첫 시도는 403 SiteVerification
  대기였고 수 시간 후 재시도에 성공). 발행 시 자동 ping도 이제 유효할 것.
- 색인 기준선 실측(네이버 검색 API·웹검색): 네이버 웹문서에 beoksolution.com은
  홈페이지 1건만 존재, 블로그 글 0건. 구글 계열도 블로그 글 0건. 회복 추적의
  비교 기준으로 삼는다.
